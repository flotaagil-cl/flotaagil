# PR de HU-11

**Rama:** `feat/HU-11-convenios` (encadenada desde `feat/HU-28-alertas`).

**Título:** `feat(web): administrar convenios con link y contraseña (HU-11)`

## Cuerpo

Closes #14

### Qué hace

- **API, solo administrador:** `/api/convenios/` para listar, crear, ver y editar, y `POST /api/convenios/{id}/rotar-password/`.
- **Credenciales:** token de 256 bits. La contraseña la genera el servidor, se guarda con hash y se muestra una sola vez.
- **RN-08:** desactivar invalida el link y no toca las reservas. Reactivar conserva link y contraseña.
- **RN-12:** rotar, activar y desactivar quedan en auditoría, sin contraseñas ni hashes.
- **Panel:** pantalla Convenios con volumen de reservas, ficha con el link, y confirmación antes de rotar o desactivar.

### Decisiones para revisar (DC-24)

- **«Define» la contraseña el servidor,** no el administrador, igual que las temporales aprobadas en HU-10: evita contraseñas débiles elegidas a mano.
- **El token solo va en el detalle,** no en el listado, porque es una credencial.
- **Sin RUT único por empresa:** el Anexo D no lo exige y un cliente puede tener más de un convenio.
- **El link se arma como `/convenio/{token}`.** HU-25 debe usar esa ruta.
